# Golden Gym

تطبيق Flutter لإدارة الجيمات، الأعضاء، الاشتراكات، الحضور، الموظفين، الحصص، المديونيات، المصروفات والنقاط.

## البنية

- تطبيق Flutter يتصل بـ REST API عبر HTTPS.
- Backend مستقل بـ Node.js 22 وPostgreSQL؛ بيانات المجالات محفوظة في JSONB، مع جداول مستقلة للحسابات والجلسات.
- عزل بيانات كل جيم والصلاحيات والتحقق من الترخيص على السيرفر.
- الجلسة محفوظة باستخدام `flutter_secure_storage`؛ كلمات المرور مشفرة بـ scrypt على السيرفر.
- إنشاء الجيم والأدمن، الاشتراك والمدفوعات، تسديد الدين، الحضور، الحجز والنقاط تتم داخل معاملات PostgreSQL ذرية.
- صور العضوية تستخدم Cloudinary كما في التطبيق الأصلي.
- تنبيهات قرب انتهاء الاشتراك تظهر داخل التطبيق. لا توجد إشعارات push عندما يكون التطبيق مغلقًا؛ إضافة مزود مستقل تتطلب إعدادًا منفصلًا.
- تحديث القوائم فور العمليات المحلية، وكل 10 ثوانٍ لتغييرات الأجهزة الأخرى. لا يوجد تعديل بيانات بلا اتصال.

قاعدة البيانات الجديدة تبدأ فارغة. لا يوجد استيراد لبيانات الاختبار السابقة.

## تشغيل الباك إند

```bash
cd backend
npm ci
```

أضف المتغيرات الموضحة في `backend/.env.example` إلى بيئة التشغيل. Node لا يقرأ `.env` تلقائيًا؛ محليًا يمكن تشغيل:

```bash
node --env-file=.env src/server.js
```

المتغيرات الأساسية:

| المتغير | الاستخدام |
| --- | --- |
| `DATABASE_URL` | رابط PostgreSQL، محفوظ على السيرفر فقط |
| `PORT` | منفذ الخدمة، الافتراضي 3000 |
| `BOOTSTRAP_ADMIN_EMAIL` | إيميل مالك النظام لأول تشغيل |
| `BOOTSTRAP_ADMIN_PASSWORD` | كلمة مرور خاصة من 8 إلى 256 حرفًا |
| `BOOTSTRAP_ADMIN_NAME` | اسم مالك النظام |
| `ALLOW_SIGNUP` | `true` لإنشاء جيم تجريبي لمدة 14 يومًا، أو `false` لإغلاق التسجيل العام |
| `CORS_ORIGINS` | مصادر الويب المسموحة، مفصولة بفاصلة؛ لا تحتاجها نسخة Android |

الجداول تتجهز تلقائيًا عند بدء الخدمة، أو باستخدام `npm run migrate`. بيانات أول مالك تستخدم فقط إذا لم يوجد مالك نظام؛ تغيير متغير الباسورد لاحقًا لا يغير حسابًا موجودًا. لا يوجد باسورد افتراضي.

للنشر على Railway: اختر هذا الريبو لخدمة الباك إند، واجعل Root Directory هو `backend`، وأضف PostgreSQL واربط `DATABASE_URL`، واضبط متغيرات أول مالك النظام. الخدمة تستخدم Dockerfile الموجود داخل `backend`. فعّل public domain واختبر `/health`؛ الرد المطلوب `{"status":"ok"}`. لا تضع رابط قاعدة البيانات في التطبيق.

للنشر على Vercel: أنشئ مشروعًا من الريبو، Root Directory هو `backend`، وFramework Preset هو `Other`. Install Command هو `npm ci --omit=dev`، وBuild Command فارغ. `backend/vercel.json` يوجّه الطلبات إلى مدخل Node ويضم ملف مخطط SQL. استخدم قاعدة Neon في Frankfurt مع المنطقة `fra1` للـ API. مشروع قاعدة الجيم الجديد هو `golden-gym` (`tiny-sun-62505649`)، بقاعدة `gym` وفرع `production`؛ لا يحتوي على البيانات القديمة.

ضع `DATABASE_URL` و`BOOTSTRAP_ADMIN_PASSWORD` في متغيرات Production السرية فقط، واضبط `BOOTSTRAP_ADMIN_EMAIL` و`BOOTSTRAP_ADMIN_NAME` و`ALLOW_SIGNUP=false`. لا تمنح Preview الوصول إلى قاعدة Production؛ استخدم فرع قاعدة مستقل لو احتجت معاينات. مدخل Vercel يفرض تغيير كلمة مرور أول مالك عند أول دخول، ويستخدم pool مشتركًا صغيرًا، ويمنع تعارض تهيئة الجداول عند تشغيل عدة نسخ. إعداد حساب Vercel قد يتطلب صلاحية إنشاء مشروع وربط الريبو.

## ربط Flutter

الخدمة المنشورة: `https://golden-gym-api.vercel.app`. هذا هو الرابط الافتراضي للتطبيق؛ `API_BASE_URL` يسمح باستخدام خدمة أخرى للتطوير. اختبار `/health` على الخدمة المنشورة أعاد `{"status":"ok"}`. بناء CI يرفع APK debug للتجربة باسم `gym-manager-test-apk` مرتبطًا بهذه الخدمة؛ هذه ليست نسخة إصدار نهائية.

```bash
flutter pub get
flutter run --dart-define=API_BASE_URL=https://YOUR-API-DOMAIN
```

محاكي Android محليًا: `http://10.0.2.2:3000`. HTTP مسموح لهذا العنوان في نسخة debug فقط؛ نسخة release تستخدم HTTPS. روابط الخدمة لا تحتوي على `/api` في آخرها.

تسجيل مالك النظام والأدمن والموظف بالإيميل. تسجيل العضو بكود الجيم ورقم الموبايل وكلمة المرور. إنشاء حساب عضو يعطي الأدمن كلمة مرور مؤقتة عشوائية مرة واحدة، ويمنع العمليات لحين تغييرها. حذف موظف يحذف الحساب والجلسات فعليًا؛ حذف عضو يلغي حساب دخوله ويحافظ على تاريخ المعاملات.

ميزة قفل الجهاز عند تسجيل الحضور تؤكد هوية الموظف صاحب الجهاز؛ لا تتعرف على بصمة العضو المختار. تسجيل الحضور يخصم يومًا واحدًا لكل عضو في اليوم بتوقيت القاهرة.

## بناء Android

المفتاح القديم العام لا يستخدم في الإصدار الجديد. هذه النسخة تحتاج تثبيتًا جديدًا إذا كان التطبيق القديم مثبتًا بتوقيع مختلف. احفظ المفتاح الخاص الجديد لإمكانية التحديثات المستقبلية.

ضع مفتاح التوقيع الخاص في `android/app/release.jks` واضبط:

- `ANDROID_STORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

```bash
flutter build apk --release --dart-define=API_BASE_URL=https://YOUR-API-DOMAIN
```

في GitHub Actions: يمكن تغيير رابط الخدمة باستخدام Repository Variable باسم `GYM_API_BASE_URL`؛ الافتراضي هو الخدمة المنشورة أعلاه. أضف Secrets باسم `ANDROID_KEYSTORE_BASE64` والمتغيرات الثلاثة الخاصة بالتوقيع أعلاه لإنتاج APK release. بدون مفتاح خاص، workflow يرفع APK debug للتجربة فقط.

## التحقق

```bash
cd backend
npm test
```

الاختبارات محليًا تستخدم PostgreSQL WASM عبر PGlite. لقاعدة PostgreSQL مستقلة استخدم `TEST_DATABASE_URL`; الاختبارات تنشئ schema منفصلًا ثم تحذفه. CI يستخدم PostgreSQL 16 ويتحقق من حسابات الدخول، عزل الجيمات، الحضور المتزامن، التحصيل المتزامن، الحجز، النقاط وإلغاء الجلسات.

```bash
flutter analyze --no-fatal-infos --no-fatal-warnings
flutter test
```

اختبارات Flutter تتحقق من شاشة الدخول، ترميز التواريخ، الجلسة المرسلة للـ API ورسائل الأخطاء وربط الاشتراكات والحضور بأوامر السيرفر.
